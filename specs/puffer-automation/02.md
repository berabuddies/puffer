# puffer-automation 02: Connector Action Review And Approval

## Summary

Automation-originated connector actions with outward effects draft first and
resume only after human approval. The product contract mirrors Monitor's
human-gated boundary: an Automation run may reach `awaiting_approval`, but no
daemon path sends an outward connector action before a reviewer approves the
draft.

## Execution Contract

Ungated `puffer_connector_action` steps execute synchronously through the
installed connector action executor. The connector result becomes
`previous_output` for the next continuation, loop, or connector action.

Top-level connector actions marked `external_side_effect`, `draft_only`, or
`human_approval_required` do not execute immediately. The daemon creates a
generic outbound connector action draft, returns a `connector_action_draft`
output, records the run as `awaiting_approval`, and stores a suspension when
there are later top-level steps to resume. Terminal top-level gated actions do
not need a suspension; approval marks the run completed after the connector
executor returns a receipt.

Suspensions are keyed by Automation run and step and persist the continuation
context needed after approval: `automation_id`, `run_id`, `step_id`, `draft_id`,
connector/action identity, the next top-level step index, `trigger_input`,
`root_output`, and `previous_output`. On approval, the daemon executes the
drafted action for real, rebuilds the connector-action result shape, and runs
the remaining top-level flow with that result as the seed `previous_output`.

Loop-body gated actions and gated first-class `Agent` tools are not supported
in this pass. Validation rejects them at save/compile time, and the runtime has
a backstop error if one reaches execution. Loop-body ungated connector actions
remain the terminal suffix described in `01.md`.

Rejecting a draft moves the corresponding run to terminal `rejected`, records a
short reviewer reason on the draft, and removes any persisted suspension for
that run. Snooze is UI-only and leaves daemon state unchanged.

## Draft Store

Automation reuses the generic outbound connector action draft store instead of
adding an Automation-specific queue. Draft records keep the existing draft
identity, version check, provenance check, approve-what-you-see content hash,
and idempotent already-sent behavior. Automation drafts add
`automation_id`, `automation_run_id`, and `step_id` so the review UI and
approval path can join a draft back to the suspended run.

Send-message drafts are editable through `approved_message`. Non-send actions
are `exact_action` drafts; if the stored input has a body-like `message_field`,
the reviewer may edit that field through `approved_input`, while destination
fields remain pinned by daemon validation. Exact actions without an editable
body field are approved as-is.

## Pending Action RPCs

`automation_pending_action_list` returns pending Automation drafts from
`outbound_action_drafts.json` with status `draft_ready` or `send_failed`. Rows
include draft identity/version, Automation/run/step ids, Automation name,
connector/action metadata, recipient metadata, approval kind, timestamps, and a
short preview. Full action input and message body are not required to render
the list.

`automation_pending_action_get` validates draft identity and provenance, then
returns the detail payload for one pending draft: the list fields plus message,
input, `message_field`, destination metadata, content hash, and any previous
send error.

`automation_pending_action_reject` requires a non-empty reason, marks the draft
`rejected`, writes `rejected_reason` and `rejected_at`, and marks the run
`rejected`.

Approval continues to use `connector_action_execute`. For Automation-originated
drafts, a successful execute either resumes the persisted suspension or marks a
terminal-position run approved/completed when no suspension exists.

## Guardrails

- Automation execution only drafts gated outward effects. The connector action
  executor may run for a gated Automation step only from the post-approval
  `connector_action_execute` path.
- Draft listings stay summary-oriented; reviewers fetch one draft detail before
  approving or rejecting.
- Content-hash/version checks and the `already_sent` short-circuit apply to
  Automation drafts exactly as they do chat-turn drafts.
