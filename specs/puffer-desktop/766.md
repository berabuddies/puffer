# Stubbed onboarding flow

Desktop onboarding now presents a staged first-run flow before entering the
workspace:

- run-mode selection, with Puffer Cloud represented as an explicit stub and
  local bring-your-own-provider as the usable path;
- provider setup, preserving the existing real provider login/import surface;
- tool connection toggles for Chrome import, passwords, Telegram, and SSH as
  local stub controls;
- learning permission toggles for browser history, shell history, and messages;
- a short local profile analysis state followed by an editable profile preview.

The flow is renderer-local state only except for existing provider auth and local
model setup calls. The provider step keeps the full setup catalog visible after
one provider is ready, allowing users to add Anthropic, OpenAI, Google,
OpenRouter, Vercel AI Gateway, GitHub Copilot, or custom providers before
continuing. It does not introduce cloud auth, connector provisioning, history
import, or profile persistence. Completion still calls the existing onboarding
finish callback, so the app-level provider gate and skip-onboarding semantics
remain unchanged.

Playwright onboarding coverage now advances through the staged stub flow before
asserting workspace entry and dismissal behavior.
