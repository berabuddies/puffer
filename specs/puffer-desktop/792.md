# Automation Review Inbox MVP

The Automation home screen now hosts the MVP review inbox for Automation-originated connector action drafts.

## Behavior

- Desktop calls `automation_pending_action_list` on Automation home load and refresh.
- List rows show summary fields only: automation name, connector/action, recipient, status, approval kind, created time, and preview.
- Opening a row calls `automation_pending_action_get` and loads the full draft detail in the side panel.
- `Approve` calls the existing `connector_action_execute` RPC with a stable client request id. `send_message` drafts send an edited `approved_message`; exact-action drafts send an edited `approved_input` only when the daemon provides `message_field`; otherwise the exact action is approved as-is.
- `Reject` requires a short reason and calls `automation_pending_action_reject`.
- `Snooze` closes the detail panel locally and does not mutate daemon state.

## Contracts

- Frontend types model the daemon's snake_case pending action fields directly.
- The list type intentionally has no full action `input` or `message` body; only detail includes `message`, `input`, `message_field`, destination metadata, content hash, and errors.
- The fake desktop daemon mirrors the MVP state transitions for `draft_ready`, `send_failed`, `sent`, and `rejected`.
- Existing Automation routing is unchanged; no new global navigation destination is added.

## Tests

- `tests/automation-ui.spec.ts` covers pending-list rendering, full-detail fetch, editing and approving, rejecting with a reason, and snoozing without an execute/reject RPC.
- `src/lib/api/desktop.workflow-daemon.test.ts` verifies the new Automation pending action wrappers are daemon-only.
