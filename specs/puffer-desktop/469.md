# Session Management Backend Wishlist (V2 / Momo)

## Summary

Desktop V2 (Momo) ships real session management in the sidebar Work / Life
groups, but the Trash affordance is shipped-disabled and group membership
lives in `localStorage` because `delete_session` and durable session
grouping/tags are not yet exposed by `puffer-session-store/`. This spec
lists the backend work needed to unblock the V2 sidebar and let us delete
the localStorage shim.

## Blocking

### `delete_session(sessionId)`

The one RPC we need to unblock the Trash icon in `Sidebar.svelte`.

- Request: `{ id, method: "delete_session", params: { sessionId } }`
- Success response: `{ type: "response", id, ok: true, result: {} }`
- Failure response: `{ type: "response", id, ok: false, error }`
- Behavior:
  - Remove the session record from `puffer-session-store/` AND delete its
    transcript JSONL on disk in the same call (no half-deleted state).
  - Idempotent — deleting an unknown sessionId returns `ok: true`. Callers
    will retry on transport errors; an unknown id is not an error from the
    UI's point of view.
  - Refuse when a turn is in-flight for the session. Return
    `ok: false, error: "session has an active turn"` (or similar — any
    structured error the UI can surface verbatim is fine). The frontend
    will re-enable Trash once `turn-complete` / `turn-error` lands.

## Nice to have

These are not blocking V2 ship but each one lets the frontend delete code.

### `create_session(... tags?: string[])`

Accept an optional `tags: string[]` on session create. V2 will persist
group membership as a tag of the form `group:work` or `group:life`. This
removes the need for the `puffer.sessionGroups` localStorage map (see
`src-v2/lib/sessionStore.svelte.ts`).

### `set_session_tags(sessionId, tags: string[])`

Atomic tag replacement. Returns the updated session record so the UI can
patch its cached row in place. Lets V2 add a "move to Work / Life" menu
item later without another backend round trip. Out of current UI scope
but cheap to ship alongside the create-time tag support.

### `session:<id>:deleted` broadcast event

Emit on the existing broadcast channel after a successful
`delete_session`. Other connected UIs / future tabs subscribed to the
session can drop their cached state instead of waiting for the next
`list_grouped_sessions` reconciliation. Strictly optional; the UI works
without it.

## Why now (rationale)

- localStorage group membership is per-machine and is wiped any time the
  user clears site data or moves to a new device — sessions then collapse
  to the "work" fallback and the curated split is gone.
- Cross-machine session listing already works (sessions sync via puffer)
  but every session shows up ungrouped on the second machine until the
  user manually re-tags them.
- The Trash icon in V2 is shipped-disabled with a `title="Coming soon —
  requires backend support"` tooltip; users will try to delete sessions
  and get blocked. We don't want this stuck state for long.
- Once tags are first-class on `SessionMetadata`, `list_grouped_sessions`
  can group by tag (or in addition to cwd) — closer to how V2 actually
  presents sessions.
- The frontend already speaks the convention `group:work` / `group:life`
  internally, so switching from localStorage to backend tags is a
  drop-in.

## Out of scope for this spec

- Agent CRUD / lifecycle.
- Assigning an agent-spec to a session at create time.
- Session forking (`parentSessionId` is in metadata but no fork RPC
  exists; V2 does not need this yet).
- Move-between-groups UI in V2 (cheap to add once `set_session_tags`
  ships, but not in the current iteration).

## Frontend code that becomes simpler

Once create-time tags + `set_session_tags` ship, the localStorage block
in `apps/puffer-desktop/src-v2/lib/sessionStore.svelte.ts` is dead code:

- `STORAGE_KEY`, `groupMap`, `readGroupMap()`, `writeGroupMap()`,
  `groupFor()` (lines ~30–76) all collapse.
- `workSessions` / `lifeSessions` (`$derived` filters) switch from
  reading `groupMap` to checking `session.tags.includes("group:work")`.
- `createSessionInGroup()` passes `tags: ["group:" + group]` straight
  into `create_session` and stops mirroring into localStorage.

Net ~20-line simplification with no UI changes required.

## Compatibility

`delete_session` is purely additive. The `tags` parameter on
`create_session` is optional and existing callers will keep working
unchanged. `set_session_tags` is a new method. The broadcast event uses
an existing channel pattern (`session:<id>:<kind>`) and unknown events
are already ignored by current consumers.
