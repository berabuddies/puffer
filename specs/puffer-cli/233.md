# Monitor Keyword Operators

`task_monitor_rule_add` keyword rules now honor the optional `operator`
parameter for Event.text.

- Missing `operator` remains backward-compatible and defaults to `contains`.
- `contains` compiles each keyword as an escaped literal regex alternative.
- `equals` compiles escaped keywords into a whole-text anchored regex.
- `matches` treats keywords as user regex patterns, validates the combined
  expression, and stores it as the text regex filter.
- `exists` is rejected for message text rules.

Field rules are unchanged: they continue to require connector event schema
metadata and compile through `compile_event_field_rule`.
