# Monitor Task Text Sanitization

## Summary

Monitor task `subject` and `description` values are sanitized when persisted through `TaskCreate` and `TaskUpdate`. Runtime persistence now enforces the content-first contract even if a monitor agent writes source-first or judgment-first text.

## Behavior

- Strip source prefixes such as `Telegram message from`, `Incoming Telegram message`, `Telegram user sent`, `In Telegram group`, and `message from chat_id`.
- Remove monitor source terms such as `Telegram` and summary boilerplate such as `message asks`.
- Drop judgment sentences containing terms such as `actionable request`, `actionable task`, `non-actionable`, or `triage`.
- Apply the sanitizer case-insensitively for ASCII source and judgment terms.
- Keep source identity in task metadata, not in the user-facing task text.

## Architecture

The sanitizer lives in the workflow task tool runtime next to monitor task metadata validation. Monitor detection uses the target monitor task store, existing monitor metadata, or incoming monitor metadata. Non-monitor task subjects and descriptions are left unchanged.

## Compatibility

Existing persisted tasks are not migrated. The sanitized text applies to future monitor task creates and future monitor task updates.

## Verification

`monitor_task_create_sanitizes_source_and_judgment_language` and `monitor_task_update_sanitizes_source_and_judgment_language` assert that monitor task text no longer persists source or judgment boilerplate while preserving the original message content and useful follow-up intent.
